# 웹접근성 Day 1 — 시맨틱 HTML과 접근성 트리 (2026-09-17)

## 개념 요약
- 브라우저는 트리를 2개 만든다: **DOM 트리**(화면용) + **접근성 트리**(보조기술용).
- 스크린리더는 화면이 아니라 **접근성 트리를 읽는다.**
- 접근성 트리의 노드는 **role(역할) · name(이름) · state(상태)** 를 노출.
- **시맨틱 태그**를 쓰면 role·name·state + 키보드 지원이 **공짜**. `div`/`span`은 껍데기 → 접근성 트리에서 증발.
- 아이콘·이미지 버튼은 **name 명시** 필요 (`aria-label` / `alt`).
- name 우선순위: `aria-label` > `aria-labelledby` > 요소 내부 텍스트 > `alt`/`<label>`.

## 문제 & 풀이

### [기초 1] div + onClick 좋아요 버튼의 문제 2가지
```jsx
<div className="btn" onClick={handleLike}>❤️ 좋아요</div>
```
1. onclick을 붙으면 대부분 button이기에 여기서 div라는 아무런의미없는 박스이기에 button인 시멘틱 태그로 대체해야함,또한 클릭 자체가 마우스로만 가능하고 탭통해 엔터 또는 스페이지로 불가
2. ① role 없음(스크린리더) ② 키보드 불가, 해결 = button으로 교체.

### [기초 2] 아이콘 닫기 버튼 — 스크린리더는 뭐라고 읽나 / 수정
```jsx
<button onClick={close}><X className="h-4 w-4" /></button>
```
1. button내에 아이콘만 있고 aria-label 없어서 아무것도 읽히지않음
2. button에 aria-label에 '닫기'로 넣거나 close로 넣어야함


### [기초 3] heading으로 인식되는 것은? 이유
```jsx
// A
<div className="text-2xl font-bold">이 책과 비슷한 책</div>
// B
<h2 className="text-2xl font-bold">이 책과 비슷한 책</h2>
```
1. heading으로 읽히는건 B 입니다.
2. 이유는 : 시멘틱 선택에 있습니다. A는 아무런의미없는 div 박스 입니다.반면 B는 제목을 의미하는 시멘틱 태그인 h2를 사용해서 제목으로 인식됩니다.


### [복습·종합] 최종 접근 가능한 이름(name)은?
```jsx
<button aria-label="장바구니에 담기">담기</button>
```
1. "aria-label > 내부 텍스트 우선순위라, '담기'는 무시되고 aria-label 값이 읽힌다."


### [상] div로 클릭요소를 만들 때 button이 공짜로 주던 것 되살리기
1. div를 클릭 요소로 만들려면 일단 aria-label를 먼저 클릭가능하다는 이름을 부여해야함. 예를들어 좋아요 버튼
2. 또한 div를 탭으로 선택가능하겠끔 tabindex를 부여해야함
3. 탭으로 이동되게할려면 role에 button을 부여해야함
4. onKeyDown에 함수도 넣어야 흉내낼수있음

## 복습 리스트 (틀린 것)
- div 버튼 고치기 = **`<button>`으로 교체** (div 안에 button 중첩 ❌, aria-label이 의미없는 게 아니라 role이 없는 게 문제)
- 버튼 흉내 role = **`role="button"`** (`role="tab"` ❌ — tab은 탭메뉴 전용)
- div 되살리기 4종세트: `role="button"` + `tabIndex={0}` + `aria-label` + **`onKeyDown`(Enter/Space)**
- 아이콘 버튼: name 없으면 "아무것도 안 읽힘"이 아니라 **"이름 없는 버튼"으로 읽힘** (role은 있음)
- 보이는 텍스트 ≠ 접근 이름이면 음성명령 사용자 혼란 → 되도록 일치
