# Vue Day 2 — computed·watch·v-if·props·emit (미니프로젝트) (2026-09-18)

> 형식: Q&A 대신 **미니 프로젝트("📚 책 담기", BookinMini)** 로 개념 적용.
> 코드: `Myvue/learning-vue-project/src/components/BookinMini.vue`, `BookCard.vue`

## 1. computed — 파생값 + 캐싱 (React `useMemo`)
- **역할**: 의존하는 반응형 값들로부터 **새 값을 계산해서 반환**. "실행"이 아니라 **"값 생성"** 이 포인트.
- **캐싱 + lazy**: 의존값 안 바뀌면 몇 번 읽어도 재계산 X (캐시 반환).
- **의존성 자동 추적**: useMemo와 달리 의존성 배열 안 적음.
- **순수해야 함**: 부수효과 X, 반환값만.
- 프로젝트 사용처: `filterBooks`(검색필터), `cartTotalPrice`(reduce 합), `cartCount`.

## 2. watch — 부수효과 (React `useEffect`인데 lazy)
- **역할**: 주시할 값이 **바뀌면** 부수효과 실행. 콜백에 `(newVal, oldVal)`.
- **핵심 차이(useEffect와)**: 기본 `watch`는 **lazy** → 진입/마운트 시 **실행 안 함.** 값이 바뀔 때만.
  - 진입 때도 실행: `{ immediate: true }` (setup 시점 1번 + 이후 변경마다)
  - 실행 타이밍: 기본 DOM 업데이트 **전**(`flush: 'pre'`) / DOM 후 원하면 `{ flush: 'post' }`
- **`watchEffect`** = useEffect에 더 가까움: **즉시 1번 + 자동추적**(source 명시 X, old/new 없음).
- 판단: **값 도출 → computed / 바뀜에 반응해 행동 → watch**
- 프로젝트 사용처: `keyword` 바뀔 때 콘솔 로그.

## 3. v-if — 조건부 렌더 (React `{cond && ...}`)
- `v-if`/`v-else-if`/`v-else`. false면 DOM에서 **아예 제거**.
- `v-show`는 CSS `display:none`(DOM 유지) — 자주 토글이면 v-show, 조건부 존재면 v-if.
- 프로젝트: 검색결과 없음 / 장바구니 빈 상태.

## 4. props / emit — 컴포넌트 통신 ("props down, events up")
- **데이터는 아래로 ↓ = props (`:`, v-bind, `defineProps`)**
- **이벤트는 위로 ↑ = emits (`@`, v-on, `defineEmits` + `emit`)**
- React는 둘 다 props 한 채널이지만, **Vue는 두 채널로 분리**.
- `:add`(프롭=값) vs `@add`(이벤트=리스너)는 **다른 것** — 이름 겹치면 헷갈리니 피하기.
- **자식은 부모 함수를 모름**: `emit('add', book)`으로 "신호"만 쏘고, 부모가 `@add`로 구독해 반응. (느슨한 결합)

### defineProps (TS 정석)
```ts
interface Props { book: Book; add?: boolean }
const props = defineProps<Props>()
// 기본값: withDefaults(defineProps<Props>(), { add: false })
```
- 선언 3형태: `['book']`(이름만) / `{ book: { type, required, default, validator } }`(런타임 검증) / `<Props>()`(TS, 권장).
- 런타임 `{}`: `type`=생성자(Object/Boolean...), `required`=필수, `default`=기본값(**객체·배열은 팩토리 `()=>({})`!**), `validator`=내 검증함수(boolean 반환, dev 경고).
- 함수도 prop 가능(반환값 받아야 할 때). 여러 개면 interface에 함수 시그니처로.

### defineEmits (TS 정석)
```ts
type Emits = { add: [book: Book] }   // 이벤트명: [payload 인자들]
const emit = defineEmits<Emits>()
```
- `add: [book: Book]` = "add 이벤트 + payload는 Book 하나". `book:`은 가독용 라벨.
- 타입 선언하면 이벤트명 오타·payload 타입 컴파일 타임 검사됨.

### props로 함수 vs emit — 언제?
- **반환값 필요** → 함수를 prop으로 (자식이 호출→반환 받음). 예: 포맷터/검증기.
- **알림만(반환 X)** → emit. `emit()`은 반환 통로 없음(단방향).
- Vue 관례: 행동 통지는 emit, 값 돌려받는 순수함수만 함수 prop.
- 중앙 가로채기(REST 미들웨어처럼) → Pinia `store.$onAction`.

## 복습 리스트 (틀린 것 / 헷갈린 것)
- `:add`(프롭) ≠ `@add`(이벤트) — 버튼 안 뜬 버그 원인. 이름 겹치지 말 것(예: `selectable`).
- computed = "값 생성+캐싱"이지 "변경시 실행"(그건 watch) 아님.
- watch는 기본 **lazy**(초기 실행 X) — useEffect와 다름. 초기 실행은 `immediate:true`.
- 객체/배열 prop `default`는 **팩토리 함수**로.
- currency 포맷(`₩`)에 `원` 또 붙이면 중복.
