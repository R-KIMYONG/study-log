# React/Next Day1 — 렌더링·리렌더·메모이제이션 (2026-09-22)

> 교재: BookIn에서 나온 "왜 이렇게 되지?"를 주제화 (실무=교재)

## 1. 렌더(render)란 — 2단계
리액트의 "렌더"는 "화면에 그리는 것"이 **아니다.** 두 단계로 쪼개짐.

- **Render Phase (렌더 단계)**: 리액트가 **컴포넌트 함수를 호출**해서, "이번엔 화면이 이렇게 생겨야 해"라는 **설계도(JSX → React element 트리)** 를 반환받는 단계. 화면엔 아무것도 안 그림 = 순수 계산.
- **Commit Phase (커밋 단계)**: 렌더 단계 결과를 이전 설계도와 **비교(diff / reconciliation)** 해서 **실제로 바뀐 DOM만** 반영하는 단계. 이게 진짜 "그리는" 부분.

## 2. 리렌더 ≠ DOM repaint ★
- **"리렌더가 일어났다" = "컴포넌트 함수가 다시 호출됐다"** (설계도 다시 계산). 화면 repaint가 아님.
- 함수가 100번 재호출돼도 **반환 JSX가 이전과 같으면** → diff 결과 "변경 없음" → **DOM은 1도 안 건드림.**
- 즉 DOM을 다시 그리는 기준 = "반환 JSX가 이전과 다른가" (상태/ props 변화로). 메모이제이션과 무관하게 모든 리렌더에서 일어나는 레이어.

| | 일어나는가 | 기준 |
| --- | --- | --- |
| 리렌더(함수 재호출) | ⭕ | 부모가 리렌더됨 등 |
| DOM repaint | 조건부 | 반환 JSX가 이전과 다를 때만 |

## 3. 리렌더 트리거 3가지
1. 자신의 **state** 변경 (setState)
2. **부모**가 리렌더됨 (props가 같아도 기본적으로 자식도 리렌더) ← 핵심 함정
3. 구독 중인 **Context** 값 변경

## 4. 메모이제이션 3형제 ★
목표: "부모 리렌더 → 자식 전부 리렌더" 기본값에서, 불필요한 재호출/재계산을 스킵.

- **`React.memo`** — 컴포넌트 재호출 스킵. props를 **얕은 비교**해서 같으면 함수 호출 자체를 건너뜀. (부모 리렌더가 아니라 **props 값 변화** 기준!)
- **`useMemo`** — **값 계산 결과** 캐싱. `useMemo(() => compute(dep), [dep])`. dep 안 바뀌면 재계산 X. → 무거운 **계산** 아낌.
- **`useCallback`** — **함수 참조(정체성)** 고정. `useCallback(fn, [dep])` ≡ `useMemo(() => fn, [dep])`. 계산 절약이 **아니라** 참조 고정.

### 핵심 개념들
- **참조 비교**: 함수/객체/배열은 "내용"이 아니라 "참조(메모리 주소)"로 비교. `()=>{}` 두 개는 생긴 게 같아도 `===` false. → 매 렌더 새 함수는 전부 남남.
- 인라인 `()=>{}`는 매 렌더 새 객체 → `React.memo` 자식의 얕은 비교를 깨뜨림 → **`useCallback`으로 참조 고정** 필요.
- **함수는 리렌더 때 재정의(생성)되지 재실행 아님.** 생성 비용은 함수 무게와 무관(≈0). "무거운 함수라 useCallback"은 오해 — 무거운 계산 캐싱은 `useMemo`(실행+결과저장), `useCallback`은 실행 안 함.
- **단독 `useCallback`은 순손해.** 참조를 소비하는 상대가 있을 때만 켠다:
  1. `React.memo`로 감싼 자식에게 props로 넘길 때
  2. `useEffect`/`useMemo`/다른 `useCallback`의 deps 배열
  3. 커스텀훅이 반환하는 함수
  → 셋 다 아니면 오버헤드만. 습관적 래핑 = 안티패턴.

## 5. BookIn 실전 판단
- `BookListView`의 `isbnList = useMemo(...)` → 새 배열 참조가 React Query queryKey로 가서 **매 렌더 refetch 방지**용. 정당.
- `CategoryItem`을 `React.memo` 안 감싼 것 → 기술적으론 dim 토글 시 스킵 이득 **있지만**, 아이템 ~20개·가벼움 → **premature optimization.** 안 감싸는 게 맞음. (근거: "memo하면 스킵되지만 이득 미미"가 정확, "props 연결돼서 어차피 리렌더"는 틀린 이유)
- `useUrlParams`/`AvatarUpload`/`ChangePassWord`의 단독 useCallback들 = 소비자 없어 순손해 → 제거 대상이었음.

## 복습 포인트
- [ ] 리렌더(함수 재호출) ≠ DOM repaint(반환 JSX 다를 때만)
- [ ] "props 연결됨" ≠ "props 바뀜" — memo는 값 변화 기준
- [ ] `useCallback`=참조 고정 / `useMemo`=값 캐싱
- [ ] 단독 useCallback = 순손해 (소비자 있을 때만)
