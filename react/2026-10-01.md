# React/Next Day2 — key & reconciliation · 커스텀훅 (2026-10-01)

## 1. reconciliation(재조정)
- Day1 복습: 리렌더 → 새 JSX 트리 → **이전 트리와 비교(diff) → 바뀐 DOM만 반영.** 이 "비교" 과정이 reconciliation.
- 리스트(`list.map`)에서 React는 "이전 렌더의 어떤 항목과 지금 항목이 **같은 항목**인가"를 판단해야 함 → 그 식별 수단이 **key**.

## 2. key의 역할 & 3조건 ★
> key = 리스트 항목의 식별자. React가 key로 "같은 항목"을 추적 → 추가/삭제/순서변경 시 **뭘 유지·이동·제거할지 정확히 판단** → DOM 재사용 + state 보존.

**key 조건 3가지 (유니크만이 아니다!):**
1. **고유(unique)** — 형제 간 중복 없음
2. **안정적(stable)** — 렌더 간 안 바뀜
3. **데이터에 결속(identity)** — 위치가 아니라 데이터의 정체성

### ⚠️ index를 key로 쓰면 안 되는 이유
- index는 **고유함**(충돌 X). 문제는 **③ 위치 기반**이라는 것.
- 리스트 고정(추가/삭제/정렬 없음)이면 index OK. 하지만 중간 삽입/삭제/정렬 시:
  - 항목이 밀리면 key(index)가 **다른 데이터**를 가리킴.
  - React는 "key 그대로네 → 같은 항목, 내용만 바뀜" → **DOM(+input state)을 그 자리에 재사용.**
  - 결과: **입력값·체크 상태가 엉뚱한 항목에 남음.** (맨 앞 삭제 → 2번째가 1번 되는데 input은 위치에 남음)

### ⚠️ random(`Math.random()`) key 안 되는 이유
- random도 **고유함**(겹칠 확률 무시). 문제는 **② 불안정**.
- 매 렌더마다 key 새로 생성 → React가 모든 항목을 "완전히 새 항목"으로 봄 → **매 렌더 전체 DOM 버리고 재생성** (재사용 0, state·focus 날아감, 성능 최악).

### 올바른 key
데이터의 **고유 id**(DB id, isbn13 등 안 변하는 값). BookIn `makeItemKey`/`getBookKey` = isbn13 기반.

## 3. 커스텀훅 ★
> `use~`로 시작하는 함수로, 여러 컴포넌트가 공유하는 **로직**(상태+effect+훅 조합)을 추출. **UI가 아니라 로직 재사용.**

### 규칙 3가지
1. 이름 **`use~`로 시작** (훅 규칙 적용 신호)
2. 내부에서 **다른 훅 호출 가능** (useState/useEffect/useQuery…) = **훅이 훅을 조합**
3. 조건문·반복문 안에서 호출 ❌ (최상위에서만)

### ⚠️ 상태를 "공유"하지 않는다
- 두 컴포넌트가 같은 `useToggle()` 호출해도 **각자 독립된 state.** 로직(코드)만 재사용, 상태는 따로.
- 상태 공유하려면 → Context / Zustand / 상위 state.

### 단, React Query 캐시는 전역 공유
- `useLike`는 자체 state는 독립이지만, 내부에서 `queryClient.setQueryData(likeKeys.detail(isbn), ...)`로 **isbn 키의 전역 캐시**에 씀.
- → 같은 책(isbn)을 보는 **모든 컴포넌트가 같이 업데이트.** "훅 때문"이 아니라 "React Query 전역 캐시(키 기반)" 때문.
- 구분: **커스텀훅 자체 state = 독립 / React Query 캐시 = 전역 공유.**

### 훅 조합의 함정
- `useMypageQueryState`가 내부에서 `useUrlParams` 호출(훅이 훅 조합). 그래서 `useUrlParams`가 불안정하면 그 **불안정이 상위 훅으로 전파**됨. (조합되니 문제도 전파)

## 4. BookIn 커스텀훅 지도
- `useLike`/`useBookmark` — 반응 뮤테이션
- `useTasteReport`/`useReactedCount` — 데이터 조회
- `useMypageQueryState`/`useUrlParams` — URL 상태 (훅 조합)
- `useDebounce` — 디바운스
