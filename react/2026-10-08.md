# React/Next Day3 — RSC(서버 컴포넌트) · 데이터패칭 · 스트리밍 (2026-10-08)

> 교재: BookIn mypage-streaming 리팩터(직접 만든 것)로 체득

## 1. Server Component vs Client Component ★
Next App Router는 **기본이 서버 컴포넌트.**

| | Server Component (기본) | Client Component (`'use client'`) |
|---|---|---|
| 실행 위치 | **서버에서만** | 브라우저 (+ 서버 1차 렌더/하이드레이션) |
| 데이터 | **직접 `await` fetch/DB** | React Query 등 |
| 가능 | async, 서버 전용 로직, 비밀키 | useState/useEffect/이벤트/브라우저 API |
| 번들 JS | **안 보냄**(가벼움) | 포함 |
| 불가 | hooks·이벤트·브라우저 API | 서버 직접 fetch·비밀키 |

**경계 규칙:**
- `'use client'` 붙이면 **그 아래로 전부 클라.**
- **클라는 서버 컴포넌트를 `import`해서 직접 렌더 못 함.** 단 **`children`/props로 넘기는 건 가능**(children 패턴):
  ```jsx
  // 서버 부모
  <ClientComp><ServerComp /></ClientComp>   // children이면 OK
  ```
- 서버가 클라를 렌더하는 건 당연히 OK.
- **서버 전용 코드(DB 직접 조회·비밀키)는 클라 컴포넌트에 못 넣음** — 브라우저엔 서버 런타임/비밀키 없음. (fetch를 서버 컴포넌트에만 두는 이유 = runtime)

## 2. 왜 RSC
- 서버에서 데이터 직접 fetch → 워터폴↓, 비밀키 서버 유지
- 클라로 가는 JS 번들↓ (서버 컴포넌트는 JS 안 감)
- 클라는 인터랙션만

## 3. 데이터패칭 패턴 (BookIn)
```
[서버] await fetch/DB → queryClient.prefetch/fetchQuery → dehydrate → <HydrationBoundary state={...}>
[클라] HydrationBoundary가 캐시 복원 → useQuery가 그 데이터로 시작(로딩 없이)
```
= **서버 prefetch → 클라 하이드레이션.** staleTime으로 하이드레이션 후 중복 refetch 방지.

## 4. 스트리밍 + Suspense
- 서버 컴포넌트가 `await`하는 동안 `<Suspense fallback>` → 준비되면 스트리밍 교체
- 껍데기 먼저, 느린 부분 나중

## BookIn 실전 매핑 (mypage-streaming)
```
page.tsx (서버, searchParams 파싱)
 └ Mypage (서버)
    ├ MypageSidebar            ← 서버, 즉시(껍데기)
    └ <Suspense fallback={section별 스켈레톤}>
        MypageContentServer (서버 async)   ← await fetch + dehydrate + section별 분기
          └ <HydrationBoundary>
              MypageContent ('use client')  ← 클라, 캐시 재사용 + 인터랙션
```
- MypageContentServer = 서버 컴포넌트(fetch) / MypageContent = 클라(인터랙션)
- Suspense = 스트리밍(껍데기 먼저) / HydrationBoundary = 서버→클라 하이드레이션
- 브라우저 검증: 추천 새로고침 시 사이드바 즉시 + 추천 모양 스켈레톤(myBooks 그리드 아님) 확인 완료

## 복습 포인트
- [ ] 서버 컴포넌트=서버만/직접 fetch/JS 안 감 vs 클라=브라우저/hooks·이벤트/JS 감
- [ ] 클라는 서버를 import 못 함, children으로만 받음 / 서버 DB코드는 클라에 못 넣음(runtime)
- [ ] 서버 prefetch→dehydrate→HydrationBoundary→클라 캐시 재사용
- [ ] Suspense=스트리밍(껍데기 먼저, 느린 건 나중), fallback이 로딩 중 화면
