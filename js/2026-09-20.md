# JS/코테 워밍업 — 해시맵 패턴 + 배열 도구 + reduce (2026-09-20)

> 루틴 외 워밍업. 코테 패턴 #1(해시맵) + JS 컬렉션/이터레이션 도구 정리.

## 오늘 푼 문제 (프로그래머스, 해시맵 패턴)
1. **신고 결과 받기** (Lv1) — Map(카운팅) + Set(중복신고 제거). result[i]=내가 신고한 사람 중 정지된 수. O(N)
2. **완주하지 못한 선수** (Lv1) — Map 카운팅. **동명이인 때문에 Set 아니고 Map**(개수 필요). O(N)
3. **두 개 뽑아서 더하기** (Lv1) — 이중 for로 합 → Set 중복제거 → 정렬. O(N²)

핵심 관용구: **`map.set(k, (map.get(k) || 0) + 1)`** (카운팅). 해시 조회 O(1)로 brute force O(N²)→O(N).

## Map / Set (언제 뭘)
- **Set** = 값 모음, 중복 자동 제거. `has`(있나) `size`(종류수). → 존재확인·유니크·중복제거. **값 불필요, "있음"만**.
- **Map** = 키→값. `get`/`set`/`has`. → 카운팅·매핑·그룹핑. **값 필요**.
- 결정: "몇 번/무슨 값" → Map · "있나/종류 몇개" → Set.
- ⚠️ **`arr.map()`(배열 메서드=행동/동사) ≠ `new Map()`(자료구조=그릇/명사)** — 이름만 같고 완전 다른 카테고리. 그릇에 담아 → 꺼내서(`...`) → 행동을 건다.

## 배열 도구 지도 (목적 → 도구 = 루프로 치면)
| 목적 | 도구 | 루프 등가 |
|---|---|---|
| 변환(길이 같음) | `map` | `for` + push(f(x)) |
| 거르기(길이 이하) | `filter` | `for` + if(조건) push |
| 누적/접기 | `reduce` | `for` + acc 업데이트 |
| 순회만(반환X) | `forEach` | `for` (부수효과 전용, undefined 반환) |
| 하나 찾기 | `find`(요소)/`findIndex`(인덱스) | `for` + if return |
| 있나없나 | `some`/`every`/`Set.has` | `for` + 조건 |

- 객체↔배열 다리: `Object.entries/keys/values`, `Object.fromEntries`, `[...set]`/`Array.from`.
- 모던: `Object.groupBy(arr, fn)` (ES2024, 그룹핑 내장).

## reduce 실전 (오늘 첫 객체 acc 성공)
**뼈대: 빈 그릇(초기값) → 각 요소로 그릇 채우기 → `return acc`.**
```js
// 카운팅 (그릇=객체+숫자)  — 직접 짜서 성공
books.reduce((acc, b) => { acc[b.genre] = (acc[b.genre] || 0) + 1; return acc; }, {});
// { 경제:2, IT:2, 소설:1 }  · O(N)
// 그룹핑 (그릇=객체+배열)
books.reduce((acc, b) => { (acc[b.genre] ??= []).push(b); return acc; }, {});
```
- 그릇: 숫자→합계 / 객체+숫자→카운팅 / 객체+배열→그룹핑. 뼈대 동일.
- ⚠️ `return acc` 안 하면 다음 acc가 undefined (제일 흔한 버그).
- **정직**: reduce vs for 성능 거의 동일 → **가독성으로 선택**. 그룹핑은 for...of도 똑같이 명확. reduce가 "고급"이라 좋은 게 아니라 **적재적소**가 실력. 지금은 for로 이해 먼저.

## 시간복잡도 (Big-O) — "n 커질 때 얼마나 나빠지나"
| 표기 | 예 |
|---|---|
| O(1) 상수 | `arr[i]`, `map.get`, `set.has`, 객체 접근 |
| O(log n) | 이분탐색(반씩 줄임) |
| O(n) 선형 | 배열 1회 순회(for/map/filter/reduce/includes) |
| O(n log n) | `sort()` |
| O(n²) 이차 | 이중 for(모든 쌍) |
| O(2ⁿ) 지수 | 부분집합 완전탐색 |

**판단법**: ① 루프 중첩 수=차수(n,n²,n³) ② 반씩 줄임=log n ③ 해시/인덱스 접근=1 ④ 정렬=n log n ⑤ 최고차항만(상수·낮은항 버림).
**핵심**: 순회 안에서 `includes`(O(n)) 또 하면 O(n²) → **Map/Set(O(1))으로 O(n)** = 코테 시간초과 해결의 핵심.

## 복습 리스트
- `map.set(k, (map.get(k)||0)+1)` 카운팅 관용구
- Map(개수/값) vs Set(존재/유니크) 결정 규칙
- `arr.map()`(행동) ≠ `new Map()`(그릇) — 이름만 같음
- `forEach`는 반환 없음(undefined) — 새 배열 만들려 push는 안티패턴(→map/filter)
- reduce 3단계: 초기값(결과모양) → acc 업데이트 → return acc
- Big-O 판단: 루프 중첩 수 세기 / 해시로 O(n²)→O(n)
